Deploy

本站是怎么上线的

这个站没有服务器，全部托管在 GitHub Pages 上。发布源只有两种选法： 从一个分支发布，或者用 GitHub Actions 发布。下面是两种方式的完整步骤。

发布源（publishing source）是 Pages 唯一认的入口：一个分支 + 该分支里的目录（/ 或 /docs）， 或者一条上传构建产物的 workflow。指错了，站点就是干净的 404。

方式 A · 从分支发布（最快）

  1. 把站点推到仓库

    本目录就是站点根目录，index.html 在最外层。推送后远端才有内容可发布。

  2. 打开 Pages 设置

    仓库 Settings → Pages → Build and deployment，Source 选 Deploy from a branch。

  3. 选分支与目录

    Branch 选 main，目录选 / (root)，点 Save。若站点放在 docs/，目录改成 /docs。

  4. 等一次构建

    Actions 里名为 pages build and deployment 的运行全绿后，访问 https://<用户名>.github.io/<仓库名>/。

bash · 推送 
git init
git add -A
git commit -m "init: TSAI site"
git branch -M main
git remote add origin https://github.com/<USER>/<REPO>.git
git push -u origin main

# 之后：Settings → Pages → Deploy from a branch → main / (root)

要不要 .nojekyll：本仓库带了一个空的 .nojekyll，用来关掉 Jekyll 处理， 这样以 _ 开头的文件/目录不会被静默丢掉。.nojekyll 必须放在发布目录里。

方式 B · 用 GitHub Actions 发布

仓库里已经带了 .github/workflows/pages.yml。启用顺序是：先把 Source 改成 GitHub Actions，再推送，否则部署会找不到站点。

配置项值缺了会怎样
permissions.pageswrite部署阶段 403
permissions.id-tokenwrite报 Get Pages site failed
environment.namegithub-pages部署被拒 / 拿不到 URL
upload-pages-artifact.path站点目录，如 . 或 dist上传空包，线上 404
.github/workflows/pages.yml 
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .          # 有构建产物时改成 dist / build / site

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4

上线后自检

bash 
# 当前发布源（最权威，比设置页更可信）
gh api repos/<USER>/<REPO>/pages --jq '{html_url, status, source}'

# 首页状态码
curl -s -o /dev/null -w '%{http_code}\n' https://<USER>.github.io/<REPO>/

# 最近一次构建结果
gh api repos/<USER>/<REPO>/pages/builds/latest --jq '{status, error}'

# 本地预览（模拟静态目录行为）
python -m http.server 8080 --directory .

常见 404 对照

症状原因修法
整站 404发布源目录里没有 index.html把入口文件挪到发布目录，或改发布源
只有样式丢失资源用了绝对路径 /assets/…改相对路径；项目主页记得加 /仓库名/ 前缀
子页面正常、首页 404目录选项选成了 /docs，文件却在根目录改回 / (root)
改了文件不更新推错分支 / CDN 缓存 / 构建未触发看 Actions 是否跑过；加随机参数验证
大小写问题Linux 构建端区分大小写统一小写文件名
